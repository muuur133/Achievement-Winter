# ❄ Achievement Winter

**Achievement Winter** — личный игровой челлендж на сезон 2026–2027 и публичный архив прохождения игр на 100% в Steam.

🌐 **[Открыть сайт](https://muuur133.github.io/Achievement-Winter/)** · **[Открыть репозиторий](https://github.com/muuur133/Achievement-Winter)**

Цель проекта — закрыть выбранную коллекцию игр на 100%, отслеживать прогресс достижений и сохранять впечатления от каждой охоты.

## ✨ Возможности

- **Общий прогресс челленджа** — количество завершённых игр, полученные достижения и время в играх.
- **Синхронизация со Steam** — статистика достижений и игрового времени загружается автоматически.
- **Проверка полноты достижений** — проект сверяет данные игрока со схемой достижений Steam и проверенными контрольными значениями.
- **Учёт семейной библиотеки Steam** — отображается информация об играх, доступных через семейный доступ.
- **Коллекция игр** — поиск, фильтры по статусу и сортировка.
- **Карточки игр** — отдельная страница с прогрессом, статистикой, оценкой и отзывом.
- **Тир-лист охоты** — ранги S, A, B, C и D отражают именно удовольствие от получения достижений, а не качество самой игры.
- **Панель владельца** — добавление игр по Steam AppID, изменение статусов, оценок, рангов и отзывов.
- **Облачное хранение** — изменения владельца сохраняются в Supabase и доступны посетителям сайта.
- **Резервное копирование** — экспорт и импорт пользовательских данных в JSON.

## ⚙️ Как работает синхронизация Steam

GitHub Actions запускает `scripts/steam_sync.py` по расписанию — каждые 15 минут. Скрипт получает данные через Steam Web API и обновляет `steam-data.json`.

Синхронизация включает:

- игровое время;
- количество полученных достижений;
- общее количество достижений;
- процент выполнения;
- доступность статистики;
- сведения о семейном доступе.

Чтобы не создавать лишние коммиты, файл обновляется только при изменении полученных данных.

### Настройка Steam API

1. Получите ключ Steam Web API на [официальной странице Steam](https://steamcommunity.com/dev/apikey).
2. Откройте настройки репозитория GitHub: **Settings → Secrets and variables → Actions**.
3. Создайте Repository secret с именем `STEAM_API_KEY`.
4. Добавьте ключ в значение секрета.
5. Запустите workflow **Sync Steam achievements** вручную через вкладку **Actions** или дождитесь планового запуска.

**Важно:** API-ключ должен храниться только в GitHub Secrets. Не добавляйте его в исходный код, JSON-файлы или README.

## ☁️ Настройка Supabase

Supabase используется для облачного хранения пользовательских данных и авторизации владельца.

1. Создайте проект в [Supabase](https://supabase.com/).
2. Создайте пользователя-владельца в **Authentication → Users**.
3. Скопируйте UUID этого пользователя.
4. Откройте файл `supabase-setup.sql` в репозитории.
5. Замените `OWNER_AUTH_USER_UUID` на UUID владельца.
6. Выполните SQL в **SQL Editor** проекта Supabase.
7. Убедитесь, что настройки проекта в клиентском коде соответствуют вашему Supabase-проекту.

Политики Row Level Security (RLS) в SQL-файле разрешают публичное чтение данных, но обновление — только авторизованному пользователю, UUID которого указан как владелец.

Для клиентского приложения используйте только **publishable/anon key**. Никогда не помещайте `service_role` или секретный ключ Supabase в браузерный код или публичный репозиторий.

## 🏆 Правило 100%

Важная особенность проекта — отображаемые Steam 100% и подтверждённое завершение челленджа не всегда одно и то же.

Для подтверждения полного завершения скрипт проверяет доступность списка достижений, совпадение данных игрока со схемой Steam и соответствие проверенному общему количеству достижений. Отдельно учитывается проверка охвата DLC.

Если Steam не предоставляет статистику или контрольные значения не совпадают, прогресс может требовать дополнительной проверки. Это помогает не засчитывать игру на 100% только по одному числу в профиле.
